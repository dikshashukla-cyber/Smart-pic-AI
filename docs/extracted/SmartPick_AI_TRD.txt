1. Technical Overview
This document specifies a maintainable implementation for SmartPick AI: a Python-based, content-driven smartphone
recommender exposed through a Streamlit interface. The first implementation should favour transparent, testable ranking over
unnecessary model complexity. Advanced ML elements are introduced only when supported by dataset quality and evaluation
evidence.

6. Recommendation Algorithm
6.1 MVP weighted ranking
 1.   Validate budget bounds and user weights.
 2.   Apply hard constraints such as budget and optional brand/5G filters.
 3.   Select the feature set available and required for the chosen mode.
 4.   Normalize numeric features using a fitted transformation; for a quick prototype, min-max scaling can be used with clearly
 documented limits.

5.   Compute feature match scores or a user preference vector.
 6.   Combine feature scores using non-negative user weights; normalize by the sum of active weights.
 7.   Sort eligible candidates descending by score and return at most Top K.
 8.   Generate explanations from actual input features and active weights.
 
6.2 Content-based similarity
Create a feature matrix from scaled numeric fields and encoded categorical/text fields. Apply cosine similarity between a user profile
or selected reference phone and candidate rows. Ensure price constraints are applied independently. Avoid double-counting
features when combining weighted ranking and similarity; document the blend and tune it using a validation set where possible.
6.3 Reproducibility and leakage
    Fit preprocessing on the training/reference dataset, then transform evaluation data with the same fitted object.
    Do not use target/relevance labels as input features.
    Use deterministic settings where randomness is involved.
    Store feature order, preprocessing configuration, dataset version, and evaluation setup.
    Do not call a hand-written weighted formula a trained ML model; label it as a ranking baseline.
 
7. Evaluation Design
A recommender needs relevance judgements to measure recommendation quality. If no genuine interaction data exists, create a
small, explicitly documented human-reviewed relevance set for representative user profiles. Synthetic relevance labels can test
code paths but cannot establish real-world accuracy.

8. Streamlit UI Technical Requirements
    Use sidebar or grouped form controls for budget, brand, and preference weights.
    Validate that minimum budget does not exceed maximum budget.
    Ensure weights are non-negative and at least one active weight is greater than zero.
    Display a useful empty state when filters return no rows.
    Render result cards or tables with name, price, available attributes, score, and rationale.
    Show dataset source, verification date, and missing-field caveats.
    Use Streamlit caching only for stable data/model loading; invalidate cache when dataset version changes.
    Keep ranking logic outside app.py so it can be tested independently.

9. Error Handling
 Condition
Expected behaviour
Missing dataset file
Show a clear setup message; do not crash with an unexplained traceback.
Missing required columns
Report the exact missing column names.
Invalid price/feature values
Validate, flag, and exclude or correct only under a documented policy.
No eligible phones
Show a no-results message and suggest broadening filters.
All weights are zero
Ask the user to enable at least one preference.
Optional column absent
Hide/disable dependent filter or feature; do not fabricate values.
Malformed CSV
Display a controlled error and log useful diagnostic details without exposing secrets.
10. Security, Privacy, and Licensing
    No account or personal data is required for the MVP.
    Do not collect feedback persistently until storage, retention, consent, and deletion rules are defined.
    Do not store API keys in source code; use environment variables or platform secrets if future integrations require them.
    Validate any future user-uploaded CSV by size, columns, types, and file handling rules.
    Verify dataset licence, attribution, and redistribution permissions before committing data.
    Do not scrape retailer websites in violation of their terms or access controls.
    Do not commit private files, local environment folders, or personal information.

12. Deployment and Operations
 1.   Create and activate a Python virtual environment.
 2.   Install dependencies from requirements.txt.
 3.   Place permitted dataset at data/phones.csv or follow documented download instructions.
 4.   Run pytest and resolve failures.
 5.   Start locally with streamlit run app.py.
 6.   Test on a clean environment and record the Python/package versions.
 7.   Deploy via a supported Streamlit hosting workflow if compatible with data and dependency requirements.
 8.   Keep a local demo and screenshots as fallback if cloud deployment is unavailable.

15. Technical Risks and Future Work
    Source data may be stale or incomplete; add provenance and refresh procedures.
    Feature weights may encode arbitrary assumptions; expose them and validate with user feedback.
    Small catalog may produce repetitive recommendations; add diversity-aware ranking.
    Cloud memory or resource limits may affect deployment; cache stable data and keep the dataset modest.
    Future improvements may include hybrid recommenders, genuine feedback, model/data versioning, scheduled data refresh, and
 broader device attributes.
